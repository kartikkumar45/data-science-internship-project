# Project Scope and Reading Guide

This repository brings together the work completed across four internship weeks. The material does not represent one single end-to-end production system; each week has a defined purpose and should be read on its own terms.

## How to read the project

### Week 1 — Planning and strategy

The Week 1 deliverable is a planning document for a hypothetical customer-churn prediction problem. Its purpose is to show how a data-science project can be scoped before modelling begins: business objective, target definition, data requirements, quality checks, feature engineering, evaluation, governance and delivery planning.

### Week 2 — Exploratory analysis framework

The Week 2 deliverable is a reusable EDA and visualisation framework. It focuses on how an analyst should inspect data quality, distributions, relationships, anomalies and segments before drawing conclusions. It is not presented as a completed analysis of a specific supplied dataset.

### Week 3 — Two complementary analytical tracks

The Python material is a machine-learning development and evaluation plan for the hypothetical churn problem. It focuses on leakage-safe preprocessing, baselines, model comparison, validation, threshold selection, interpretation and monitoring.

The R material is executable statistical/predictive analysis using the Breast Cancer Wisconsin (Diagnostic) dataset. It includes hypothesis tests, correlation and multicollinearity checks, logistic regression, random forest, held-out testing, cross-validation and diagnostics.

These two tracks are intentionally labelled separately so that a reviewer can distinguish a planned workflow from an executed analysis.

### Week 4 — Communication and decision support

The final deliverable focuses on turning analytical work into a clear executive narrative. Its visual examples are illustrative/mock material and are not presented as measured business results.

## Quality and integrity principles

- Do not treat a plan as evidence that a model was trained.
- Do not treat an illustrative chart as a real business finding.
- Do not infer causality from correlation alone.
- Do not publish private, confidential or credential information.
- Cite external datasets and sources where required.
- Keep reproducibility instructions aligned with the actual files in the repository.

## Current repository limitation

The GitHub connector used to maintain this repository can create and edit text/code files, but it does not provide a binary DOCX/PDF upload operation. The original report documents therefore still need to be uploaded through GitHub's web interface or through a local Git workflow before the repository is considered complete.
