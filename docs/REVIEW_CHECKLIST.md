# Public Review Checklist

This checklist is used before the repository is submitted as an internship project.

## Content integrity

- [x] Plans are labelled as plans.
- [x] Illustrative/mock material is not presented as measured business performance.
- [x] The R analysis is identified as an educational classification exercise.
- [x] No fabricated model metrics have been added.

## Repository hygiene

- [x] README explains the project without unnecessary marketing language.
- [x] Work is separated by week and analytical track.
- [x] `.gitignore` covers common local/environment artefacts.
- [x] Dataset handling is documented.
- [x] No credentials or private information should be committed.

## Reproducibility

- [x] The R script documents its package requirements and expected input filename.
- [x] A fixed random seed is used in the R workflow.
- [ ] Final report files (PDF/DOCX) still need to be uploaded through GitHub's web UI or a local Git workflow.
- [ ] The dataset source/citation should be checked immediately before any dataset redistribution.

## Final submission gate

The repository should only be submitted after the final report files are present and the public page has been opened once from a logged-out/incognito browser to confirm that the intended content is visible.
